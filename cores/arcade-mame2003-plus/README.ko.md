# MAME 2003-Plus — 넷플레이가 어긋나지 않게 하는 상태 저장

> 이 코어는 MAME 2003-Plus 의 **비공식 수정판**이에요. 이 판의 문제를 원본 개발자에게 물어보지 마세요. ROM · BIOS · 세이브는 이 저장소에 없어요. ROM 은 직접 가진 것만 쓰세요.

## 무엇을 하나

MAME 2003-Plus 는 옛 오락실 보드를 아주 많이 돌려 주는 레트로아크 코어예요. 레트로아크 넷플레이(같이하기)는 방장(호스트)의 '지금 상태'를 손님(게스트)에게 보내고, 손님이 거기서부터 이어받는 방식이에요. 그러려면 상태 저장에 게임이 필요로 하는 값이 모두 들어 있어야 하는데, 원래 코어는 그렇지 못한 경우가 많았어요. 이 판은 세 가지를 고쳤어요.

- **손님 화면이 비어 있거나, 첫 장부터 달랐어요.** 보드마다 꼭 필요한 값(CPU 안에 들고 있는 값 · 타이머 · 인터럽트 대기줄 · 화면 칩의 비디오 메모리 등)이 상태에 빠져 있었어요.
- **어떤 게임은 넷플레이를 시작조차 못 했어요**(상태 저장 · 되감기도 못 썼어요). 코어가 '저장할 수 없는 게임'이라고 잘못 판단했기 때문이에요.
- **일부 보드는 상태가 너무 컸어요**(20~53MB). 바뀌지 않는 큰 롬 뱅크를 상태마다 통째로 담았거든요. 넷플레이는 되감기용 상태를 수십 개 들고 있어서 RAM 1GB 기기의 메모리가 모자랐어요.

목표는 더 정확한 에뮬레이션이 아니라 넷플레이 · 상태 저장이 되는 것이에요. 소리 칩 일부는 아직 상태에 없어서, 손님이 붙은 직후 소리가 잠깐 어긋날 수 있어요([한계](#한계) 참고).

## 무엇을 고쳤나

패치 8장을 원본 커밋 `61305d6` 위에 순서대로 쌓았어요. 코드 주석이나 기록 줄에 `hanbang` 이 들어 있는 곳은 '우리가 고친 곳 표시'일 뿐이고, 이름은 바꾸지 않았어요.

1. **상태 저장을 빠짐없이 채웠어요** (패치 0001 · 0003 · 0005 ~ 0008). 많은 보드가 등록된 상태 밖에 값을 들고 있었거나, 불러온 뒤 다시 만들어야 하는 파생 값을 다시 만들지 않고 있었어요. 빠진 값은 상태에 등록하고, 파생 값은 불러온 직후 다시 만들게 했어요.
   - 0001 은 가장 넓은 패치예요(39개 파일, +835 / -81). CPU 스케줄러(프레임 · vblank · CPU 멈춤 · 지역 시계 · 64비트 사이클), 영구 타이머(위상 · 순서), IRQ 이벤트 대기줄, 빠져 있던 T-11 · M6809 · Z80 레지스터, YM2151 타이머, 보드별 사설 비디오 메모리 · 레지스터 · 래치를 상태에 담아요. 파생 캐시는 불러온 뒤 다시 만들고, 포인터는 주소 대신 오프셋으로 저장해요. 코어 버전 문자열에 `-blankfix1` 도 붙여요. 다루는 보드 계열: Nintendo Vs. · Bally Sente · Taito SJ · Atari System 2 · MegaSys1 · Sega System 1 · Taito L · Leland / Ataxx · DECO 카세트 · HD63484 · Namco ND-1(YGV608) · Paradise · Toaplan 1 · Williams · Super Qix.
   - 0003 · 0005 · 0007 · 0008 은 보드 계열을 하나씩 더해요([패치](#패치) 표 참고). HuC6280 CPU 와 HuC6270 화면 칩, Atari GT 보드, Atari System 1 / Gauntlet, Vs. System 의 MMC3 매퍼와 보호 카운터예요.
   - 0005 는 `atarigen.c` 의 버그도 고쳐요. `UINT8` 변수 5개를 `INT32` 로 잘못 등록해서 저장 · 불러오기가 옆 메모리를 덮어썼어요.
   - 0006 은 0005 를 좁혀요. 0005 의 영구 타이머가 다른 아타리 보드의 방장 화면을 바꿔 놓아서, 영구 타이머는 `atarigt` 에서만 쓰고 나머지 보드는 원래 `timer_set` 으로 되돌렸어요.
2. **잘못된 '저장 불가' 판정을 없앴어요** (0002). `GAME_DOESNT_SERIALIZE` 가 `0x0420` 으로 정의돼 있었는데, 이 값은 `GAME_IMPERFECT_SOUND`(`0x0400`) + `GAME_WRONG_COLORS`(`0x0020`)와 정확히 같아요. 그래서 '소리가 불완전함' 또는 '색이 틀림' 표시가 붙은 게임이 모두 저장 불가로 처리돼 상태 크기가 0 으로 보고됐고, 넷플레이가 시작조차 못 했어요. 이 겹침은 2018년부터 소스에 있었어요(원본 쪽 집계로 약 323개 게임이고, 우리 게임 목록의 2인 이상 MAME 2003-Plus 215개 중에는 13개예요). 값을 겹치지 않는 비트 `0x0800` 으로 바꾼 한 줄 고침이에요.
3. **큰 롬 뱅크를 상태에서 뺐어요** (0004). 바뀌지 않는 뱅크(수 MB ~ 48MB)까지 상태마다 담아서 상태가 20~53MB 였고, 넷플레이는 되감기용 상태를 수십 개 들고 있어요. `register_banks()` 가 쓰기 지도에 한 번도 안 나오는 1MB 이상 뱅크(= 롬)를 건너뛰고, 건너뛴 뱅크마다 `hanbang: read-only bank` 기록 한 줄을 남겨요.

### 확인한 것 (측정)

시험 방법은 모두 같아요. 방장 A 가 20초 또는 60초 진행한 뒤 상태를 저장해요. **새 프로세스**의 손님 B 가 같은 ROM 을 켜고 2장 뒤 그 상태를 불러와요. 입력 없이 300장을 진행하며 장마다 원본 픽셀의 해시를 방장과 견줘요(`300/300` 은 한 장도 안 다르다는 뜻이에요). 방장 쪽 영상이 고치기 전 코어와 같은지도 같이 봤어요(에뮬 동작을 안 바꿨는지 확인하려고요). 이 시험은 맥과 가상 머신에서 했고, 실제 기기 시험은 따로 있어요.

### 한계

- 입력 없는 시험이 중심이에요. 동전 · 두 사람 입력 · 지연 · 되감기 · 소리 맞춤은 대표 게임만 기기에서 봤어요.
- 소리 칩 일부(PC엔진 C6280 · MSM5205 · TMS5220 · POKEY 내부 값)는 아직 상태에 없어요. 손님이 붙은 직후 소리가 잠깐 어긋날 수 있어요.
- 상태가 커진 보드가 있어요(CAGE 계열 1.59MB → 2.27MB). 되감기용 상태를 여러 개 들고 있으니 메모리도 그만큼 더 들어요.
- 상태가 맞아도 **기기 속도**가 모자라면 소용없어요. ST-V 계열은 혼자서도 초당 30~40장, CAGE 소리 기판 계열은 약 46장(제 속도의 77%)이라 넷플레이용으로는 쓰지 않아요.
- 롬이 없어 못 돌린 드라이버: `tmek`, Midway V-Unit(같은 DSP 코어). 롬이 없던 일부 아타리 드라이버는 방장 화면 회귀 시험만 했어요.

## 코어 옵션

추가하거나 바꾼 옵션은 없어요. 코어 정보에서 눈에 띄는 차이는 `-blankfix1` 로 끝나는 버전 표시뿐이에요.

## KNULLI 에 넣기

[최신 릴리스](https://github.com/Squirbie/handheld-link-cores/releases/latest)에서 `arcade-mame2003-plus-linux-aarch64.zip` 을 받아 풀어 주세요. 우리가 넣은 방식은 이래요.

1. **파일 자리**: `/userdata/system/hanbang_cores/mame2003_plus_libretro.so` (미리 빌드한 파일이 쓰는 기본 자리), SD 카드 쪽이에요. 레트로아크가 찾는 `/usr/lib/libretro/mame2003_plus_libretro.so` 는 이 파일로 가는 **바로가기(심볼릭 링크)** 예요. 코어를 SD 쪽에 둔 건 KNULLI 의 덧칠(overlay)이 램 디스크라 큰 파일을 넣으면 메모리를 먹기 때문이에요. 이 폴더를 지우면 아케이드 일부가 안 켜져요.
2. **바꾸는 순서**: 게임이 안 돌고 있을 때(EmulationStation 의 로컬 웹 API `runningGame` 이 "NO GAME")만 바꿔요. 새 파일을 `mame2003_plus_libretro.so.hbnew` 로 보내고, md5 를 맞춰 보고, `chmod 755`, `mv -f` 로 바꿔치기한 뒤 `sync` 해요. 바꾸기 전에 원래 파일을 같은 폴더에 옛 이름으로 보관하세요(우리는 `.bf7` 같은 꼬리를 붙였어요). 레트로아크는 게임을 켤 때 코어를 읽으니 따로 껐다 켤 필요는 없어요.
3. **두 기기는 반드시 같은 파일**이어야 해요. 다른 판이 섞이면 상태 크기가 달라 손님이 못 붙어요. 둘 다 md5 를 확인하세요.
4. **게임별로 쓰기**: 이 코어가 그 기종의 기본이 아니면 `knulli.conf` 에 한 줄을 넣어요. `arcade["<ROM 이름>.zip"].core=mame2003_plus`
5. **확인**: md5, 그리고 코어 정보의 버전이 `61305d6-blankfix1` 인지 봐요. 레트로아크 기록을 켜 두면, 큰 뱅크가 있는 게임을 켤 때 `hanbang: read-only bank` 줄이 떠요.
6. **되돌리기**: 보관한 파일을 다시 놓으세요. 이전 판으로 만든 상태 파일은 이 판에서 안 열리고 반대도 마찬가지예요(우리는 넣기 전에 두 기기에 오락실 상태 저장 파일이 0개인 것을 확인했어요).

### 다른 기기 · OS 에서 쓸 때 주의

- **파일은 aarch64 리눅스 전용**이에요. 32비트 ARM · x86 · 안드로이드 · 윈도우 · 맥에서는 못 써요. 패치를 원본 소스에 걸어 그 기기용으로 빌드하세요.
- **glibc 2.33 이상**(libm 2.29 이상)이 필요해요(Debian 12 의 GCC 12.2 로 빌드했어요). 그보다 오래된 리눅스에서는 그 기기에서 다시 빌드해야 해요. KNULLI 에서는 문제없었어요.
- **넷플레이는 양쪽이 같은 파일일 때만** 시험했어요. 원본 코어나 다른 판과 섞으면 손님이 못 붙거나 어긋나요.
- **상태 파일은 서로 호환되지 않아요.** 이 판은 상태에 담는 항목이 원본이나 앞 단계 판과 달라서, 그것들로 만든 상태 · 자동 저장은 못 불러오고 반대도 같아요.
- **메모리**: 보드에 따라 상태가 커지거나(0005) 작아져요(0004). 램이 1GB 인 기기에서 시험했어요.
- 시험은 RG35XX Pro(H700) + KNULLI + RetroArch 1.22 에서만 했어요. 다른 프런트엔드의 넷플레이 구현은 확인하지 않았어요.

### 같이 쓰는 스크립트

## 소스에서 빌드

우리는 Debian 12 (aarch64) 환경의 GCC 12.2.0 으로 원본 소스 폴더에서 그냥 `make` 했어요(메모리가 모자라 `-j1`). 결과는 glibc 2.33 이상이 필요해요.

```sh
git clone https://github.com/libretro/mame2003-plus-libretro.git
cd mame2003-plus-libretro
git checkout 61305d60329d6a9abf7ddad1c3657b3253c5e64d
for p in /경로/patches/000*.patch; do git apply --check "$p" && git apply "$p" || break; done
make              # 램이 넉넉하면 -jN 을 붙이세요. aarch64 리눅스에서는 platform=unix 로 자동 설정돼요
# 결과: mame2003_plus_libretro.so
```

- 같은 환경에서도 파일 지문(md5)이 똑같이 나온다는 보장은 없어요(컴파일러 버전 · 빌드 경로). 우리 빌드의 정확한 명령줄 · 옵션은 기록에 남아 있지 않아요.
- 맥에서 컴파일만 확인하려면(결과는 `dylib` 이에요):
  ```sh
  make -j6 platform=osx ARCH=arm64 'CC=clang -std=gnu89 -fcommon -Dfdopen=fdopen -Wno-error=incompatible-function-pointer-types'
  ```
- 패치를 `git` 저장소 안에서 걸면 코어 정보의 버전 표시가 `<짧은 해시>-blankfix1` 이 돼요.

### 확인한 것과 못 한 것

- **확인함**: 8장이 깨끗한 원본(`61305d6`) 위에 번호 순서대로 한 번에 걸려요. `0001` 의 "고치기 전" 파일 지문(`index` 줄)도 이 커밋의 파일과 맞아요(2026-10-29).
- **확인함**: 최종 `.so` 안 글자가 패치와 맞아요. `hanbang: read-only bank`(0004), `VSindex` · `security_counter` · `prot_index` · `mirror_reg`(0008), `HuC6270_vram` · `adpcm_toggle`(0003), `expanded_mram` · `protmode`(0005), `next_timer_scanline` · `playfield_yscroll_applied` · `trakball_cur`(0007), `cpu_scheduler`(0001)가 모두 들어 있고, 버전 표시가 `61305d6-blankfix1` 이에요.
- **확인함**: 패치를 건 소스가 맥(Apple clang 21, arm64)에서 오류 없이 컴파일 · 링크돼요(2026-10-29, 경고 끔). 올라가 있는 파일은 aarch64 리눅스 GCC 로 따로 빌드한 것이라 이 맥 `dylib` 과는 다른 파일이에요.
- **0008 메모**: 스크립트 버전이 아니라 완성된 diff 를 썼어요. 스크립트만 돌리면 `#include "state.h"` 와 `VSindex` 등록 두 줄이 빠지고 diff 에는 들어 있어요(최종 코어 안에 `VSindex` 가 있는 것과 맞아요).
- **못 함**: 0002 판 코어(`cd9cc09f`)는 파일이 남아 있지 않아 기록으로만 확인했어요. 기기용 빌드의 정확한 명령줄 · 옵션은 기록에 없어요. 이 폴더의 소스로 aarch64 코어를 새로 빌드해 md5 를 대조하지는 않았어요. 0001 이 건드린 29개 보드 파일 중 일부(`decocass` · `leland` · `taitosj` · `williams` 머신 파일 등)는 원본 쪽 이력 조회가 API 한도에 걸려 비교하지 못했어요.

## 라이선스

MAME 2003-Plus 는 옛 **MAME 비상업 라이선스**(MAME 0.78 사용 · 배포 라이선스)예요. 전문은 원본의 `LICENSE.md` 에 있고, 이 저장소에도 [`LICENSES/mame2003-plus-libretro_LICENSE.md`](../../LICENSES/mame2003-plus-libretro_LICENSE.md) 로 사본을 두었어요. 이 패치 · 고친 코어도 같은 조건이에요. 요점은 이래요.

- MAME 는 비영리 프로젝트예요. **소스든 바이너리든 팔 수 없어요.** 이 코어를 넣은 기기나 카드를 돈 받고 파는 것도 안 돼요.

- ROM 은 저작물이에요. 불법 ROM 과 같은 매체로 나누면 안 돼요. 이 저장소에는 ROM 이 없어요.
